Variables and Sequence

Every variable is DECLAREd before it is used, with a type. Assignment uses the left-pointing arrow, not an equals sign.

Declare, then assign

DECLARE Age : INTEGER
DECLARE Name : STRING
Age <- 16
Name <- "Aiko"
  • 1DECLARE Name : TYPE fixes what kind of value a variable can hold, before it is ever assigned.
  • 2The type after the colon must match every value later stored in it.
  • 3<- is assignment. It reads as "becomes", never "equals".
  • 4A STRING value is always wrapped in double quotes.

Input and output

OUTPUT "Enter your age "
INPUT Age
OUTPUT "You are ", Age, " years old"
  • 1Every INPUT should have an OUTPUT prompt directly before it, so the user knows what to type.
  • 2INPUT Age stores whatever the user types straight into Age.
  • 3Commas combine several values into one OUTPUT line, mixing text and variables freely.

The main data types

INTEGER   // whole numbers
REAL      // decimals
CHAR      // one character
STRING    // text
BOOLEAN   // TRUE or FALSE

Selection

A decision the program makes while it runs. Always close IF with ENDIF.

IF / THEN / ELSE

IF Age >= 18
  THEN
    OUTPUT "Adult"
  ELSE
    OUTPUT "Minor"
ENDIF
  • 1The condition after IF must evaluate to TRUE or FALSE.
  • 2THEN starts the branch that runs when the condition is TRUE.
  • 3ELSE is optional. Leave it out if there is nothing to do when the condition is FALSE.
  • 4ENDIF closes the whole block. Every IF needs exactly one.

Combining conditions

IF Age >= 13 AND Age <= 19
  THEN
    OUTPUT "Teenager"
ENDIF
  • 1AND needs both sides to be true.
  • 2OR needs only one side to be true.
  • 3NOT flips a condition from TRUE to FALSE or back.

Iteration

Three loop shapes. Pick the one that matches how many times the loop should run.

FOR: count-controlled, you know how many times in advance

FOR Index <- 1 TO 10
  OUTPUT Index
NEXT Index
  • 1The loop variable starts at 1 and stops after it reaches 10, inclusive.
  • 2NEXT Index must name the same variable the FOR line started.

WHILE: pre-condition, checked before each pass, may run zero times

INPUT Number
WHILE Number < 1 OR Number > 10 DO
  OUTPUT "Out of range, try again "
  INPUT Number
ENDWHILE
  • 1This is the standard validation-loop shape: input once before the loop.
  • 2The condition is tested BEFORE every pass, including the first.
  • 3Input again only happens INSIDE the loop, never before it a second time.

REPEAT: post-condition, checked after each pass, always runs at least once

REPEAT
  OUTPUT "Enter a password (at least 10 characters) "
  INPUT Password
UNTIL LENGTH(Password) >= 10
  • 1REPEAT needs no separate INPUT before it. The loop body always runs once.
  • 2The condition is tested AFTER the pass, at UNTIL.
  • 3The loop keeps going UNTIL the condition becomes TRUE, the opposite of WHILE.
Common mix-up: read your own condition back to yourself before submitting. WHILE keeps looping while its condition is TRUE. REPEAT...UNTIL keeps looping until its condition becomes TRUE, so the wording of the two conditions usually looks opposite even for the same rule.

Arrays

A fixed collection of values of the same type, accessed by index. Bloomsbury Computing's pseudocode indexes start at 1.

DECLARE Scores : ARRAY[1:30] OF INTEGER
Scores[1] <- 55
FOR Index <- 1 TO 30
  INPUT Scores[Index]
NEXT Index
  • 1[1:30] means the array holds elements at index 1 through 30, inclusive.
  • 2Every element must hold the same type, given after OF.
  • 3A FOR loop with the same range as the array is the standard way to fill or read every element.

Before You Submit

  • Every variable DECLAREd before it is assigned or read.
  • Every IF has a matching ENDIF; every FOR has a matching NEXT; every WHILE has a matching ENDWHILE.
  • Every INPUT has an OUTPUT prompt just before it explaining what to type.
  • Read your own condition back to front. Does the loop actually stop when you think it does?
  • Indent the lines inside IF, FOR, WHILE and REPEAT so the structure is easy to read.
